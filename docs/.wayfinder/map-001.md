# Wayfinder Map: Lab Tools Dashboard

**Label:** `wayfinder:map`
**Status:** ACTIVE

## Destination

A locally-running browser dashboard with 3-5 interactive scientific tools
(calculators + plotters) that non-coding lab coworkers can open and use
immediately. Built well enough that it looks intentional, not generated.
The developer (PR) learns web fundamentals along the way.

## Notes

- Domain: crystallography, X-ray scattering, diffraction
- Developer has zero web experience, strong Python/numpy background
- Skills to consult: `/grill-with-docs`, `/tdd`, `/prototype`
- Design skills: `/impeccable` (install: `npx impeccable install`), `/design` (Claude Design at claude.ai/design for mockups)
- Design reference: see DESIGN.md (Nolde Museum + Seaborn + Frans Hals Museum aesthetic)
- Pace: side project, no deadline — learning is a primary goal
- Anti-goal: avoid "AI slop" — every design choice should be deliberate
- This map doubles as a wayfinder tutorial — the first real use of the skill

## Tickets

### TICKET-001: Choose the web tech stack [grilling]
**Type:** grilling (HITL)
**Status:** OPEN
**Blocks:** TICKET-003, TICKET-004, TICKET-005

The key tradeoff: something simple enough to learn from scratch (plain
HTML/CSS/JS) vs. something that makes dashboards easier (React, Svelte,
etc.) vs. Python-based web frameworks (Streamlit, Panel, Gradio) that
leverage existing skills.

Question: What framework/approach should we use, given zero web experience,
a desire to actually learn, and the need for fast interactive widgets?

### TICKET-002: Define the first 3-5 tools [grilling]
**Type:** grilling (HITL)
**Status:** OPEN
**Blocks:** TICKET-004, TICKET-005

What specific calculators and plotters should be in v1? Candidates from
existing repos and common lab needs:
- d-spacing / Bragg angle calculator
- X-ray energy/wavelength converter
- Scattering geometry plotter (like xrdPlanner)
- Peak fitting viewer
- Unit cell parameter calculator
- Resolution estimator

Question: Which tools give the most value to your coworkers, and which
are tractable as a first web project?

### TICKET-003: Build a "hello world" with chosen stack [task]
**Type:** task (HITL)
**Status:** OPEN
**Blocked by:** TICKET-001

Scaffold the project with the chosen tech stack. Get a page running locally
with one input and one output — type a number, see it doubled. Purpose:
verify the dev environment works and PR understands the edit-reload loop.

### TICKET-004: Design the dashboard layout [prototype]
**Type:** prototype (HITL)
**Status:** OPEN
**Blocked by:** TICKET-001, TICKET-002

Create 2-3 radically different layout mockups for the main dashboard page.
Use `/impeccable init` (feeds from DESIGN.md) to establish the design system,
then `/prototype` for layout variations. Optionally use Claude Design
(claude.ai/design) for visual mockups. Reference sites: Nolde Museum (warm
spacing, expressive palette), Seaborn (tool gallery thumbnails), Frans Hals
Museum (bold modern typography, horizontal browsing). See DESIGN.md for
full analysis.

### TICKET-005: Build the first tool end-to-end [grilling + task]
**Type:** grilling → task (HITL)
**Status:** OPEN
**Blocked by:** TICKET-001, TICKET-002, TICKET-004

Pick the simplest tool from TICKET-002's list, grill through its exact
inputs/outputs/edge cases, then build it. This is the first real
deliverable — and the template for every tool after it.

## Not yet specified

- How to package/share with coworkers (local server? USB? simple file share?)
- Whether calculations should also run in Python (pyodide) or pure JS
- Testing strategy for scientific correctness (known-answer tests?)
- How to handle unit systems and significant figures
- Whether to support data file upload or just manual input for v1
- Mobile/tablet support (do coworkers use this at the beamline?)
- How to add new tools over time without redesigning everything

## Out of scope

- Server deployment / cloud hosting (explicitly deferred)
- User accounts or authentication
- Database / persistent storage of results
- Connecting to live instrument data streams
